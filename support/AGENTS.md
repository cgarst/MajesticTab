# Support and marketing assets

Website, store listing, and branding material live in `docs/` and `support/`:

- `docs/`: the public website (GitHub Pages root: `index.html`, `site.css`, `privacy.html`, `CNAME`, `fonts/`, `img/`, `icons/`), the deploy root for `majestictab.zathu.net`.
- `support/store/`: App Store screenshots from the real iOS 27 Simulator and Mac window (`appstore-ios/`, `appstore-ipad/`, `appstore-duo/`, `appstore-mac/`, made by `support/tools/simulator_screenshots.py`; see its header, it needs Xcode 27 and `agent-device`), the App Store header and search-result art (`appstore-art/`) and GitHub social preview (`github/`, both from `apple_marketing_art.py`, which reads the iPhone and iPad raw captures); Microsoft Store screenshots and logos (`msstore/`), Play desktop screenshots (`play/desktop/`, which the Play API can't upload) and Flathub screenshots (`flathub/`). Flathub requires real window captures with native decorations, so `support/tools/flathub_screenshots.mjs` drives the installed release Flatpak on a KDE Wayland machine and captures it with Spectacle (never compose or emulate them); see the script header for how to run it.
- `support/listing/`: the single source for store listing text on every channel (`short_description.txt`, `full_description.txt`, `changelogs/<version>.txt`). `promotional_text.txt` is the App Store promotional text (170 characters at most; it can change without a new build), linked into `fastlane/metadata/ios/en-US/` with the description. `fastlane/metadata/android/en-US/` holds the Google Play and F-Droid listing images (icon, feature graphic, phone and tablet screenshots) plus symlinks to that text. `msstore_listing.py` reads the same descriptions and release notes. `fastlane android listing` syncs the listing to Play and `fastlane android release` uploads the AAB (`bundle exec`, with `PLAY_SERVICE_ACCOUNT_JSON` set). `fastlane ios listing` and `mac listing` sync the App Store text and screenshots, `ios beta` and `mac beta` upload the builds to TestFlight (App Store Connect API key in `.env`, see the top of the Apple lanes in `fastlane/Fastfile`).
- `support/branding/`: source icon SVGs and `generate_icons.py`, which writes the web PNG/ICO icons to both `src/icons/` and `docs/icons/`.
- `support/tools/`: generators (`store_screenshots.py` for the browser-made Android, Windows and website shots, `simulator_screenshots.py` and `apple_marketing_art.py` for Apple, `store_logos.py`, `generate-steam-artwork.mjs`, `generate-msstore-artwork.mjs`, `flathub_screenshots.mjs`) and `landing/capture.mjs`, which captures the website's pictures from the real app (`docs/img/app/*.webp` and the hero loop `hero.webm`/`hero.mp4`, Slate Blue, `Duo No 2` fixture only; see its header for how to run it, and re-run it before each release so the site matches the app). The website is hand-written (`docs/index.html`, `docs/site.css`), flat and built on the look rules in `agents/ui-principles.md` (sentence case, no eyebrows, see `agents/ui-copy.md`); there is no CSS build step. `chord-voicings/` holds the chord library's note and playability rules plus its check and repair scripts (see `chord-voicings/AGENTS.md`).

Runtime app icons are in `src/icons/` (referenced as `icons/...` from `src/`).
